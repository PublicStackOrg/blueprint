# Migrating a Public Service from blueprint v0.1.0 to v0.2.0

`publicstack upgrade --to 0.2.0` is still a stub command. Until it lands,
follow this guide manually for any Public Service generated from blueprint
v0.1.0. The sections are independent — apply only the ones relevant to
your Public Service.

## What changed in v0.2.0

Phase 4 of `blueprint/docs/PLAN.md`:

- The Grid format was finalized — six contracts, two formats (OpenAPI 3.1 +
  JSON Schema 2020-12). See `blueprint/grid/`.
- `publicstack-contracts` CLI shipped (`blueprint/contracts/tooling/`) for
  validating and diffing Contract files.
- Three new Grid services have adapter slots: `payments`, `audit`,
  `accessibility`.
- The `storage` Grid service was renamed to `document_storage` to match
  PLAN.md §1's vocabulary.
- A new Alembic migration `0002_audit_log` adds an `audit_log` table for
  the default `PostgresAuditAdapter`.
- `services/api/api/dependencies.py` now wires all six Grid adapters via
  FastAPI DI.
- `.env.example` adds env vars for each new adapter.
- `publicstack add grid <service>` was added to the `publicstack` CLI.

## Migration steps

### 1. Rename `storage` to `document_storage`

```bash
git mv libraries/grid_adapters/grid_adapters/storage \
       libraries/grid_adapters/grid_adapters/document_storage
```

Update imports across the repo:

```bash
grep -rl "from grid_adapters.storage" . --include="*.py" \
  | xargs sed -i '' 's/from grid_adapters.storage/from grid_adapters.document_storage/g'
```

If your `services/api/api/dependencies.py` had `get_storage_adapter` referring
to the old `LocalFilesystemAdapter`, the import path is the only change —
the class name is unchanged.

### 2. Drop old `STORAGE_*` env vars

In `.env.example` and any `.env` files:

```diff
-STORAGE_BACKEND=local
-STORAGE_LOCAL_PATH=./storage
+DOCUMENT_STORAGE_BACKEND=local
+DOCUMENT_STORAGE_LOCAL_ROOT=./document_storage
```

If your code reads `STORAGE_BACKEND` / `STORAGE_LOCAL_PATH` directly
(through `APISettings`), rename the field in `services/api/api/config.py`
to `document_storage_backend` / `document_storage_local_root`.

### 3. Add the new Grid adapter slots

For each of `payments`, `audit`, `accessibility`:

```bash
publicstack add grid payments
publicstack add grid audit
publicstack add grid accessibility
```

This writes `grid/<service>.yaml` and copies a bundled adapter stub into
`libraries/grid_adapters/grid_adapters/<service>/` if missing. Idempotent.

### 4. Apply the audit-log migration

The new Alembic revision is `0002_audit_log`. Copy the file from
`blueprint/template/{{cookiecutter.public_service_name}}/services/migrator/migrations/versions/0002_audit_log.py`
into your Public Service's `services/migrator/migrations/versions/` dir,
then:

```bash
docker compose up -d db migrator
```

The migrator will run the new revision against your database.

### 5. Wire all six adapters in `dependencies.py`

The reference shape is at
`blueprint/template/{{cookiecutter.public_service_name}}/services/api/api/dependencies.py`.
The pattern is one provider per adapter; see the existing `get_identity_adapter`
(unchanged from v0.1.0) for the shape. New providers:

- `get_audit_adapter(session, settings)` — `PostgresAuditAdapter`
- `get_storage_adapter(settings)` — `LocalFilesystemAdapter` (renamed)
- `get_notifications_adapter(settings)` — `LogOnlyAdapter` (now async)
- `get_payments_adapter(settings)` — `LogOnlyPaymentsAdapter`
- `get_accessibility_adapter()` — `InMemoryAccessibilityAdapter`

### 6. Update `NotificationsAdapter` callers (breaking)

The `NotificationsAdapter` Protocol changed shape to match the Grid
notifications contract:

```diff
- adapter.send(to="x@example.com", subject="Hi", body="...")
+ await adapter.send(channel="email", to="x@example.com", template_id="welcome",
+                    vars={"name": "Pat"})
```

Find call sites and update:

```bash
grep -rn "adapter.send" services/ libraries/
```

### 7. Bump `BLUEPRINT_VERSION`

```bash
echo 0.2.0 > BLUEPRINT_VERSION
```

### 8. Re-run tests

```bash
docker compose up -d db migrator
poetry run pytest libraries/grid_adapters/tests/test_audit_postgres.py
poetry run pytest
```

## Verifying the upgrade

- `publicstack-contracts validate grid/identity.yaml` should not fail (the
  YAML is just config; the Grid contract itself is upstream at
  `blueprint/grid/identity/contract.yaml`).
- `cat BLUEPRINT_VERSION` prints `0.2.0`.
- `docker compose up` brings the stack up green.
- `services/api/api/dependencies.py` imports all six Grid adapters without
  error.

## Reverting

This guide does **not** include a downgrade path. Revert via git: stash or
branch your in-progress upgrade work; check out your last v0.1.0 commit;
re-run the migrator to apply only `0001_initial_items` (or restore from
backup if you already ran `0002_audit_log` against production).

## When `publicstack upgrade` ships

Eventually `publicstack upgrade --to 0.2.0` will automate steps 1-7 above.
For now, manual is the path. Open an issue on `PublicStackOrg/blueprint` if
you hit something this guide doesn't cover.
